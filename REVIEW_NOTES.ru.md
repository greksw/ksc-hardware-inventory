# Ревизия трёх обезличенных скриптов и статус проверки

Дата ревизии: 2026-10-22. Источник: отдельный присланный владельцем ZIP из `gateway_probe.py`, `ram_pilot.py`, `import_result.py`. Этот публичный комплект **не содержит** исходный ZIP ревизии, предыдущие версии скриптов или реальные сведения о сети.

## Что сохранено из проверенного пилота

1. Подключение `KlAkAdmServer.Create(..., verify=<CA>)` к KSC Open API 15.1 по DNS-имени сертификата.
2. `HostGroup.FindHosts` по точному `KLHST_WKS_FQDN`; получение Host GUID из `KLHST_WKS_HOSTNAME`, человекочитаемого имени из `KLHST_WKS_DN`; обязательная проверка GUID.
3. `CgwHelper.GetNagentLocation` → `GatewayConnection.PrepareGatewayConnection` → `server.Disconnect()` → `KlAkAdmServer.CreateGateway` c проверкой сертификата.
4. Использование `NagRdu` для загрузки ZIP и `ExecuteFileAsync`, ожидание `KlAkAsyncActionStateChecker.CheckActionState` и получение результата через `LastActionResult`.
5. ZIP-результат `result/ram-*.json`, передача валидированного JSON через отдельную учётную запись SSH без передачи токена Inventory на управляющий компьютер.

## Что изменено и почему

| Область | В обезличенном пилотном коде | В переработанной версии |
|---|---|---|
| Режим работы | Последовательный запуск при выполнении файла | `preflight` (офлайн по умолчанию), `probe` (чтение), `collect` (явное выполнение) |
| Цель | Условные DNS/имя/GUID в коде | Настройка через CLI/переменные окружения, три независимые сверки |
| Запуск PowerShell | После подключения без дополнительного подтверждения | Требует `--confirm-computer`, `--collector` и проверенного SHA256 ZIP |
| Права TLS | Проверка CA уже была настроена | Сохранена для обеих сессий; запрет HTTP/подключения по IP |
| Возврат результата | Файл перезаписывался общим именем | Уникальное имя ZIP, приватные права на каталог и файл |
| Валидация JSON | Компьютер + наличие timestamp + непустой массив | Имя, UTC, числа, модули, суммы RAM и размер/структура ZIP |
| Импорт | После каждого сбора без отдельного разрешения | По умолчанию выключен; `--send` только при явных SSH параметрах |
| Аудит | Подробное логирование внутренних KSC error fields | Штатный безопасный вывод; исключения SDK не печатаются полностью |
| PowerShell KSC | Использовался локальный ZIP за пределами трёх исходников | Приложен адаптированный вариант; проверен на действующем KSC 15.1 с одним Windows-компьютером 22.10.2026 |

## Повторная проверка на действующем KSC (22.10.2026)

После первоначальной автономной ревизии оператор проверил финальный код на **одном** одобренном Windows-компьютере:

1. 27 автономных тестов (`unittest`) прошли; аудит 30 исходных текстовых файлов не выявил очевидных утечек.
2. Собран KSC diagnostic ZIP и пройден `preflight`, без подключения к KSC.
3. `probe` подтвердил TLS-проверенное соединение к Administration Server и Gateway, точное имя устройства и его KSC Host GUID, а также доступ `NagRdu.GetCurrentHostState()`.
4. `collect` выполнил один асинхронный запуск на агенте и получил `finalized successfully (state=1)`; скачанный ZIP содержал статус, stdout и JSON.
5. JSON прошёл проверку: четыре модуля физической памяти, суммарно 8 GiB.
6. Команда `python -m ksc_inventory.import_result` сначала прошла без отправки, затем отдельно с `--send` через пользователя SSH с принудительной командой; Inventory API ответил `HTTP 201` / `stored`.
7. На принимающем сервере проверено появление отдельной новой записи SQLite.

Имена компьютеров, домены, GUID, IP, Action ID и результаты отчётов в публичной версии протокола намеренно не приводятся. Сведения получены от оператора из вывода команд и не являются результатом независимого аудита серверной инфраструктуры.

## Что не проверено

- **Единый вызов** `ksc_runner --mode collect --send` (сбор и автоматическая отправка в одном процессе): проверялись отдельный `collect` без `--send` и последующий `import_result --send`.
- Выполнение на нескольких хостах, очередь, параллелизм, повторяемость после ошибок, планировщик.
- Сценарий ротации сертификатов KSC после смены основного и резервного сертификата.
- Полнота инвентаризации на иных BIOS/SMBIOS и платформах DDR4/DDR5.

Публичная версия пригодна как **протестированный одиночный пилот**, а не как готовый механизм массового удалённого выполнения.
