# Протокол интеграционной проверки KSC Hardware Inventory

**Дата:** 22 октября 2026 года. **Версия кода:** v0.2.0, без изменения логики в документационном релизе v0.2.1.

## Контур проверки

- Kaspersky Security Center 15.1 (Open API), Python 3.12 и KlAkOAPI.
- Один предварительно утверждённый физический Windows-компьютер с Network Agent.
- TLS с проверкой сертификата издателя, согласованного по отдельному административному каналу.
- Linux-сервер Inventory: ограниченный SSH-пользователь с `restrict,command=...`, локальный HTTPS API и SQLite.

## Ограничения подтверждения

Тест выполнен на одном реальном узле и подтверждает конкретную последовательность, а не работу всего парка. Цепочка **`collect --send` одной командой** отдельно не проверялась. Обработка тайм-аутов и ошибок подтверждена модульными тестами, но не всеми вариантами отказа реального KSC. Не публикуются реальные DNS/IP, GUID, идентификаторы заданий и выгрузки оборудования.

## Следующие условия для расширения

Ограничение прав учётной записи KSC на конкретные группы устройств, тесты на DDR4/DDR5, очередь с аудитом и управлением параллелизмом, отдельная проверка полного `collect --send`, контроль ротации TLS-сертификатов, мониторинг и резервное копирование Inventory SQLite.
